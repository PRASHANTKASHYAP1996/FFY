# Phase 5 Release Gate Checklist

## A. Security + Integrity (must pass)

- [ ] Firestore rules deployed and validated in staging.
- [ ] Storage rules deployed (`profile_photos/{uid}/**` owner-write only, `image/jpeg|image/png|image/webp`, under 5 MB).
- [ ] Callable App Check enforcement is `enforce` in production.
- [ ] No client path can mint wallet/reputation fields.
- [ ] `public_users` projection excludes deleted/disabled/admin-blocked/hidden users.

## B. Data Correctness

- [ ] Run `backfillPublicUsers_v1` once after deployment.
- [ ] Run `backfillFollowersCount_v1` once after follower mirror rollout.
- [ ] Confirm `followersCount`, `level`, `listenerRate` are server-authoritative.
- [ ] Validate chat role semantics with lexically reversed UIDs.
- [ ] Validate `actualListenerId` for both chat-open and call-open flows.

## C. Payments Honesty

- [ ] Production UI does not show placeholder legal/support/refund copy.
- [ ] Payment and withdrawal UI copy is neutral unless live operations are actually enabled.

## D. Android Release

Repo-side package/Firebase alignment is currently verified by `scripts/verify-release-readiness.ps1`. Keep the checked items below from regressing, and complete the unchecked external release items before a signed store build.

- [x] Gradle application id resolves to `com.friendify.app`.
- [x] Release build guard no longer fails on `com.example.*`.
- [ ] Release build guard no longer fails on missing `FRIENDIFY_AGORA_APP_ID`.
- [ ] Release keystore configured via `android/key.properties`.
- [ ] Release build is signed with the upload key (not the debug key).
- [x] `android/app/google-services.json` replaced with the Firebase file for `com.friendify.app`.
- [x] `lib/firebase_options.dart` regenerated for the final Android app id after package migration.
- [x] `flutterfire.json` regenerated by `flutterfire configure` after final Android app registration.
- [x] `flutterfire.json` Android app id matches the final `android/app/google-services.json` client for `com.friendify.app`.
- [ ] Firebase App Check for Android release uses Play Integrity.
- [ ] Debug App Check remains limited to debug/dev workflows only.
- [ ] Flutter `FRIENDIFY_AGORA_APP_ID` matches Functions `AGORA_APP_ID`.
- [ ] `AGORA_APP_CERTIFICATE` is set on Functions before call testing or release.
- [ ] Legal/support release defines are set for the signed build:
  - `FRIENDIFY_PRIVACY_URL`
  - `FRIENDIFY_TERMS_URL`
  - `FRIENDIFY_REFUND_URL`
  - `FRIENDIFY_SUPPORT_URL` or `FRIENDIFY_SUPPORT_EMAIL`
- [ ] Repo-side verifier passes: `powershell -ExecutionPolicy Bypass -File .\scripts\verify-release-readiness.ps1`
- [ ] Signed release smoke test completed on a real device after the final build.

## E. Validation Setup

Before running release checks, prepare both workspaces explicitly.

### Flutter

1. `flutter clean`
2. `flutter pub get`
3. `flutter analyze`
4. `flutter test`
5. Run a call-capable build with `--dart-define=FRIENDIFY_AGORA_APP_ID=<matching-agora-app-id>` for release/staging validation.
6. Run `powershell -ExecutionPolicy Bypass -File .\scripts\verify-release-readiness.ps1` from the repo root before `flutter build appbundle --release`.
7. Release builds must include:
   - `FRIENDIFY_APP_CHECK_MODE=release`
   - `FRIENDIFY_AGORA_APP_ID=<matching-agora-app-id>`
   - `FRIENDIFY_PRIVACY_URL=<https-url>`
   - `FRIENDIFY_TERMS_URL=<https-url>`
   - `FRIENDIFY_REFUND_URL=<https-url>`
   - `FRIENDIFY_SUPPORT_URL=<https-url>` or `FRIENDIFY_SUPPORT_EMAIL=<support-email>`
8. Replace all placeholder example values with real release values before shipping.
   Startup readiness checks reject literal placeholders such as:
   - `YOUR_REAL_*`
   - `<matching-agora-app-id>`
   - `<https-url>`
   - `<support-email>`

### Functions

1. `cd functions`
2. `npm ci`
3. `npm test`
4. `npm run check`
5. `npm run check:chat-contract`
6. `npm run check:migrate-chat-docids`

## F. Manual QA (exact)

1. Create two users A/B where `uid(A) > uid(B)` lexically.
2. A requests chat/call from marketplace.
3. B sees the incoming request and can allow/deny correctly.
4. A can only start a call when the session allows it.
5. Open Recent Chats from both devices and confirm the chat opens with the correct listener direction.
6. Block/delete/admin-block a test user and verify it disappears from discovery and public projection.
7. Follow/unfollow several users from A and confirm **A's** level does not increase from self-following behavior.
8. Confirm follower target count changes for the followed user only.
9. Upload and delete a profile photo at `profile_photos/{uid}/...` with owner and non-owner accounts.
10. Confirm oversized or non-image profile photo uploads are rejected by Storage rules.

## G. Deploy Sequence

1. `firebase deploy --only "firestore:rules,firestore:indexes,storage"`
2. `firebase deploy --only "functions"`
3. Run backfills (`backfillPublicUsers_v1`, `backfillFollowersCount_v1`).
4. Verify admin dashboard, marketplace, and chat request inbox in the production project.

## H. Final Package Migration Steps

1. Final Android package id: `com.friendify.app`.
2. Move `android/app/src/main/kotlin/com/friendify/app/MainActivity.kt` into the final package directory and update its Kotlin `package` line.
3. Set `ORG_GRADLE_PROJECT_FRIENDIFY_APP_ID=com.friendify.app` for release builds, or set `friendify.appId=com.friendify.app` in `android/local.properties`.
4. Do not rely on a Dart define to change the Android package; Gradle controls `applicationId`.
5. Create or confirm the matching Firebase Android app for `com.friendify.app`.
6. Replace `android/app/google-services.json` with the file for `com.friendify.app`.
7. Run `flutterfire configure --project=friendify-ef682 --platforms=android` and commit the regenerated `lib/firebase_options.dart` and `flutterfire.json`.
8. Add upload/app-signing SHA fingerprints in Firebase.
9. In Firebase App Check, keep Debug provider for debug/dev only and enable Play Integrity for the final Android release app.
10. Confirm the repo-side verifier no longer blocks on stale `google-services.json`, stale `flutterfire.json`, or stale `lib/firebase_options.dart`.
11. Confirm the Gradle release guard no longer blocks on stale `google-services.json` or stale `lib/firebase_options.dart`.
12. Run the repo-side verifier and then complete a signed release smoke test on a real device before shipping.
